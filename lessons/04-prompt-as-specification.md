# Урок 4. Промпт как спецификация задачи для агента

## Цель
Научиться писать постановки, которые агент может выполнить и проверить без лишних уточнений.

## Ключевые понятия
context, constraints, definition of done, output contract, risk boundaries.

## Подготовка окружения

Перед уроком активируйте `py11` и установите базовые зависимости:

```bash
conda activate py11
pip install openai python-dotenv
```

Убедитесь, что в `config.env` задана модель через `OPENAI_MODEL` или оставьте значение по умолчанию из примеров. Это позволит сразу проверять разные prompt-спецификации на одном и том же API router.

## Теория: 10-15 минут

- Хороший агентный prompt похож на mini-spec: контекст, цель, ограничения, доступные источники, критерии готовности.
- Нужно явно описывать, что считать успехом: тесты, скриншоты, формат отчета, список файлов, допустимые изменения.
- Запреты так же важны, как указания: не менять публичный API, не трогать секреты, не делать destructive commands.

## Яркий пример
Плохой prompt: “почини регистрацию”. Хороший prompt: “воспроизведи ошибку регистрации при пустом email, исправь только client validation, добавь тест, запусти npm test и верни diff summary”.

## Практика: 15-25 минут

- Перепишите 3 расплывчатые задачи в agent-ready формат.
- Добавьте к каждой задаче ограничения и definition of done.

## Мини-тест
1. Что делает prompt агентно-готовым?
   - A. Проверяемый результат и ограничения
   - B. Больше прилагательных
   - C. Только вежливый тон
2. Что такое definition of done?
   - A. Критерии, по которым задача считается завершенной
   - B. Название урока
   - C. Список моделей
3. Какой запрет полезен для coding agent?
   - A. Не менять unrelated файлы
   - B. Никогда не читать код
   - C. Всегда удалять тесты

## Ответы
1. A — Проверяемый результат и ограничения
2. A — Критерии, по которым задача считается завершенной
3. A — Не менять unrelated файлы

## Домашнее задание
Создать библиотеку из 5 reusable prompts: bugfix, feature, research, refactor, QA.

## Критерий готовности
Слушатель может объяснить архитектурное решение урока, применить его к новому сценарию и назвать минимум один риск неправильного применения.
