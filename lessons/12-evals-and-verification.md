# Урок 12. Проверка результата: evals, тесты, артефакты и критики

## Цель
Понять, как сделать результат агента проверяемым, а не основанным только на доверии к ответу модели.

## Ключевые понятия
acceptance criteria, unit tests, browser checks, structured outputs, LLM-as-judge, external verifier.

## Подготовка окружения

Перед уроком активируйте окружение и установите базовые зависимости:

```bash
conda activate py11
pip install openai python-dotenv
```

Проверьте `config.env`. Для упражнений подготовьте папку для артефактов проверки: test logs, screenshots, structured outputs и reviewer notes.

## Теория: 10-15 минут

- Агент должен завершать работу не фразой “готово”, а доказательством: тесты, скриншоты, логи, structured output, проверка критериев.
- Самокритика полезна, но слабее независимой проверки инструментом, тестом или отдельным reviewer-agent.
- Evals нужны не только для моделей, но и для workflow: измерять точность, полноту, стоимость, скорость и устойчивость.

## Яркий пример
QA-agent для веб-формы генерирует тестовые сценарии, запускает браузерные проверки, сохраняет скриншоты и отмечает, какие acceptance criteria покрыты.

## Практика: 15-25 минут

- Напишите acceptance criteria для агента поддержки.
- Выберите eval metrics для research-agent.

## Мини-тест
1. Что сильнее всего доказывает корректность code-agent?
   - A. Пройденные релевантные тесты и проверка сценария
   - B. Уверенный тон
   - C. Длинный отчет
2. Что такое structured output?
   - A. Ответ в заранее заданной схеме
   - B. Любой красивый текст
   - C. Скриншот
3. Зачем external verifier?
   - A. Проверить результат независимо от основного агента
   - B. Увеличить число ролей
   - C. Заменить требования

## Ответы
1. A — Пройденные релевантные тесты и проверка сценария
2. A — Ответ в заранее заданной схеме
3. A — Проверить результат независимо от основного агента
