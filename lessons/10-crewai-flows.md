# Урок 10. CrewAI Flows и управляемая оркестрация

## Цель
Отличать автономную команду агентов от управляемого workflow и понимать, когда нужны CrewAI Flows.

## Ключевые понятия
Flow, start, listen, router, event-driven workflow, typed state, branching.

## Подготовка окружения

Перед уроком активируйте окружение и установите зависимости для CrewAI Flows:

```bash
conda activate py11
pip install openai python-dotenv crewai
```

Для deterministic Flow из примера LLM не обязателен, но `config.env` все равно должен быть подготовлен: следующие уроки будут сравнивать Flow с LLM-агентами и crews.

## Теория: 10-15 минут

- Crews оптимальны для автономного сотрудничества ролей, Flows — для предсказуемых событийных процессов.
- Flow позволяет смешивать обычный код, LLM-вызовы, условия, ветвления и crews внутри одного управляемого pipeline.
- Для production часто нужен баланс: автономия внутри шагов и строгий контроль между шагами.

## Яркий пример
Onboarding-agent: принять клиента, классифицировать тариф, выбрать сценарий обучения, запустить crew для подготовки персонального письма, поставить follow-up.

## Практика: 15-25 минут

- Выберите Crew или Flow для трех сценариев: блог-пост, возврат денег, исследование рынка.
- Нарисуйте router для onboarding workflow.

## Практический запуск

Запустите CrewAI Flow с ветвлением:

```bash
conda activate py11
python course-ai-agents/examples/10_crewai_flow_onboarding.py
```

Сравните этот пример с Crew из урока 9: здесь важнее контроль маршрута, а не автономная ролевая дискуссия.

## Мини-тест
1. Когда лучше Flow?
   - A. Когда нужен явный контроль ветвлений и состояния
   - B. Когда надо просто распределить творческие роли
   - C. Когда нет бизнес-логики
2. Что делает router?
   - A. Выбирает следующий путь выполнения
   - B. Пишет все тексты
   - C. Отключает state
3. Какой подход часто лучше в production?
   - A. Смешать контролируемый workflow и автономные шаги
   - B. Полностью убрать проверки
   - C. Оставить один длинный prompt

## Ответы
1. A — Когда нужен явный контроль ветвлений и состояния
2. A — Выбирает следующий путь выполнения
3. A — Смешать контролируемый workflow и автономные шаги
