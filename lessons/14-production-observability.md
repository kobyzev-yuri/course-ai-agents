# Урок 14. Production-подход: observability, стоимость, latency, качество

## Цель
Понять, как переводить агентный прототип в надежную систему с метриками, логами и управлением стоимостью.

## Ключевые понятия
tracing, token usage, latency budget, quality metrics, fallback, incident review.

## Подготовка окружения

Перед уроком активируйте окружение и установите зависимости для запуска и измерения примеров:

```bash
conda activate py11
pip install openai python-dotenv langgraph crewai
```

Проверьте `config.env`. Для production-разбора заведите локальный файл или таблицу наблюдений: latency, token usage, tool calls, errors, retries и human escalations.

## Теория: 10-15 минут

- Production-agent должен быть наблюдаемым: видно входы, решения, tool calls, ошибки, стоимость и качество результата.
- Стоимость и latency растут с количеством агентов, инструментов, retries и проверок. Архитектура должна иметь budget.
- Fallback paths нужны для деградации: эскалация человеку, упрощенный режим, повтор позже, безопасный отказ.

## Яркий пример
Support-agent отслеживает resolution rate, escalation rate, среднюю стоимость ответа, hallucination reports и время до первого полезного действия.

## Практика: 15-25 минут

- Выберите 8 метрик для production research-agent.
- Опишите fallback для ошибки внешнего API.

## Мини-тест
1. Какая метрика помогает контролировать стоимость?
   - A. Token/tool usage per task
   - B. Цвет кнопки
   - C. Число заголовков
2. Что делать при неуверенном результате агента?
   - A. Запустить verifier или эскалировать человеку
   - B. Скрыть предупреждение
   - C. Отправить как есть
3. Зачем tracing?
   - A. Видеть путь выполнения и причины результата
   - B. Уменьшить размер экрана
   - C. Заменить тесты полностью

## Ответы
1. A — Token/tool usage per task
2. A — Запустить verifier или эскалировать человеку
3. A — Видеть путь выполнения и причины результата
