# Урок 6. Память и состояние: от контекста диалога к управляемому workflow

## Цель
Разобраться, когда агенту нужен state object, краткосрочная память, долговременная память и checkpointing.

## Ключевые понятия
short-term memory, long-term memory, state schema, reducers, context vs state, checkpoint.

## Подготовка окружения

Перед уроком активируйте окружение и установите зависимости для работы с состоянием:

```bash
conda activate py11
pip install openai python-dotenv langgraph
```

`config.env` должен содержать `OPENAI_BASE_URL`, `OPENAI_API_KEY` и опционально `OPENAI_MODEL`. LangGraph понадобится для перехода от абстрактного state object к графу с управляемыми обновлениями.

## Теория: 10-15 минут

- Контекст диалога удобен для краткой работы, но плохо подходит для надежного процесса с ветвлениями и паузами.
- Состояние должно быть явным: какие поля меняются, кто их обновляет, как объединяются частичные результаты.
- В LangGraph state schema и reducers помогают контролировать, как узлы workflow читают и обновляют данные.

## Яркий пример
Research-agent хранит query, найденные источники, подтвержденные факты, черновик и список unresolved questions как отдельные поля state.

## Практика: 15-25 минут

- Спроектируйте state model для агента поддержки.
- Отметьте поля, которые можно перезаписывать, и поля, которые нужно накапливать.

## Мини-тест
1. Когда нужен explicit state?
   - A. Когда workflow длительный, ветвящийся или возобновляемый
   - B. Только для короткого приветствия
   - C. Никогда
2. Что делает reducer?
   - A. Определяет, как объединяются обновления state
   - B. Ускоряет интернет
   - C. Меняет цвет UI
3. Что лучше хранить в long-term memory?
   - A. Устойчивые предпочтения и исторические факты
   - B. Каждый токен reasoning
   - C. Случайный черновик

## Ответы
1. A — Когда workflow длительный, ветвящийся или возобновляемый
2. A — Определяет, как объединяются обновления state
3. A — Устойчивые предпочтения и исторические факты
