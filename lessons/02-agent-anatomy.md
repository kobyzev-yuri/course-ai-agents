# Урок 2. Анатомия агента: модель, инструкции, инструменты, память, среда

## Цель
Разложить агента на архитектурные компоненты и понять ответственность каждого слоя.

## Ключевые понятия
LLM core, system instructions, tool registry, runtime environment, memory, guardrails.

## Подготовка окружения

Перед уроком активируйте окружение и проверьте базовую конфигурацию LLM:

```bash
conda activate py11
pip install openai python-dotenv
```

В `config.env` должны быть `OPENAI_BASE_URL`, `OPENAI_API_KEY` и, желательно, `OPENAI_MODEL`. Эти переменные нужны, чтобы разбирать агента не абстрактно, а на runnable-примере.

## Теория: 10-15 минут

- Модель генерирует решения, но агентность появляется только в связке с инструкциями, инструментами и циклом наблюдения.
- Инструкции задают роль, границы поведения, формат результата и правила безопасности.
- Среда выполнения определяет, что агент реально может сделать: читать файлы, запускать команды, ходить в браузер, дергать API.

## Яркий пример
Агент для подготовки отчета получает тему, ищет источники, складывает найденные факты в состояние, пишет черновик и запускает отдельный шаг проверки против списка требований.

## Практика: 15-25 минут

- Нарисуйте блок-схему агента-исследователя.
- Отметьте, какие данные должны жить в контексте, а какие в долговременной памяти.

## Мини-тест
1. Что задает границы поведения агента?
   - A. System/developer instructions
   - B. Размер монитора
   - C. Имя пользователя
2. Где лучше хранить прогресс long-running задачи?
   - A. В управляемом состоянии/checkpoint
   - B. Только в последнем сообщении
   - C. В названии файла
3. Что означает runtime environment?
   - A. Место и права, где агент выполняет действия
   - B. Список тем курса
   - C. Стилизация интерфейса

## Ответы
1. A — System/developer instructions
2. A — В управляемом состоянии/checkpoint
3. A — Место и права, где агент выполняет действия

## Домашнее задание
Составить спецификацию агента в формате: роль, цель, инструменты, ограничения, формат ответа, критерии качества.

## Критерий готовности
Слушатель может объяснить архитектурное решение урока, применить его к новому сценарию и назвать минимум один риск неправильного применения.
