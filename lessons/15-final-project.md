# Урок 15. Финальный проект: спроектировать агентную систему под реальную задачу

## Цель
Собрать все элементы курса в целостную архитектуру агентной системы и защитить проект по инженерному чеклисту.

## Ключевые понятия
architecture design, state model, tool map, human gates, eval plan, risk review.

## Подготовка окружения

Перед финальным проектом установите полный набор зависимостей курса:

```bash
conda activate py11
pip install -r course-ai-agents/examples/requirements.txt
```

Проверьте `config.env` с `OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1`, `OPENAI_API_KEY` и выбранной `OPENAI_MODEL`. Для защиты подготовьте отдельную папку проекта с диаграммой, state model, tool map, eval plan и security checklist.

## Теория: 10-15 минут

- Финальный проект проверяет не знание названий фреймворков, а способность выбрать архитектуру под ограничения задачи.
- Хороший проект объясняет, почему выбран Antigravity, LangGraph, CrewAI или их комбинация.
- Архитектура должна включать проверку результата, безопасность, стоимость и план наблюдаемости.

## Яркий пример
QA automation agent: Antigravity для разработки и проверки в браузере, LangGraph для графа сценариев и checkpointing, CrewAI для генерации тест-кейсов командой ролей.

## Практика: 15-25 минут

- Выберите один сценарий и заполните architecture canvas.
- Проведите peer review проекта другого участника по rubric.

## Мини-тест
1. Что обязательно должно быть в финальной архитектуре?
   - A. Цель, tools, state, gates, evals, risks
   - B. Только список моделей
   - C. Только красивый prompt
2. Как выбрать фреймворк?
   - A. По требованиям к контролю, скорости прототипа и среде работы
   - B. По самому длинному README
   - C. Случайно
3. Что показывает зрелость проекта?
   - A. Проверяемость, безопасность и план наблюдаемости
   - B. Отсутствие ограничений
   - C. Максимум агентов

## Ответы
1. A — Цель, tools, state, gates, evals, risks
2. A — По требованиям к контролю, скорости прототипа и среде работы
3. A — Проверяемость, безопасность и план наблюдаемости

## Домашнее задание
Подготовить финальную защиту: схема, state, tools, human gates, evals, risks, rollout plan.

## Критерий готовности
Слушатель может объяснить архитектурное решение урока, применить его к новому сценарию и назвать минимум один риск неправильного применения.
