# Урок 11. Multi-agent архитектуры: параллельность, делегирование, конфликт результатов

## Цель
Научиться выбирать multi-agent паттерн под задачу и управлять рисками координации.

## Ключевые понятия
manager-worker, peer review, specialist agents, parallel execution, conflict resolution, consensus.

## Подготовка окружения

Перед уроком подготовьте полный набор зависимостей для multi-agent сравнений:

```bash
conda activate py11
pip install openai python-dotenv langgraph crewai
```

Проверьте `config.env` и заранее решите, какая модель будет использоваться через `OPENAI_MODEL`. Для Antigravity подготовьте workspace, где можно параллельно запускать code/test/review сценарии.

## Теория: 10-15 минут

- Multi-agent подход оправдан, когда задача естественно делится на роли, требует независимой проверки или параллельной работы.
- Больше агентов не всегда лучше: растут стоимость, latency, вероятность противоречий и сложность отладки.
- Нужен явный механизм объединения результатов: manager, verifier, voting, scoring rubric или deterministic merge.

## Яркий пример
В Antigravity три агента работают параллельно: feature-agent пишет код, test-agent добавляет тесты, review-agent ищет регрессии и несоответствия acceptance criteria.

## Практика: 15-25 минут

- Для задачи “запуск новой функции” предложите 3-agent архитектуру.
- Опишите, как разрешить конфликт между researcher и reviewer.

## Мини-тест
1. Главный риск multi-agent системы?
   - A. Несогласованные результаты и сложность координации
   - B. Слишком мало ролей в названии
   - C. Отсутствие markdown
2. Когда peer review agent полезен?
   - A. Для независимой проверки результата
   - B. Чтобы дублировать ту же работу без критериев
   - C. Чтобы скрыть ошибки
3. Что должен делать manager-agent?
   - A. Делегировать, собирать и оценивать результаты
   - B. Всегда писать финальный код сам
   - C. Игнорировать state

## Ответы
1. A — Несогласованные результаты и сложность координации
2. A — Для независимой проверки результата
3. A — Делегировать, собирать и оценивать результаты

## Домашнее задание

## Критерий готовности
Слушатель может объяснить архитектурное решение урока, применить его к новому сценарию и назвать минимум один риск неправильного применения.
